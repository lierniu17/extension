# Pagenter 安全修复

## 问题陈述

还原工作按产物原样保留了几处安全隐患（见 `docs/specs/2026-11-16-pagenter-reverse.md` 补充说明）。现在任何网页都能通过 `window.__pagenter` 用我配置的模型额度、读写当前会话的 KV、以我的登录态调用已暴露的接口；任何 localhost 页面都能让 Hub 去连一个任意端口；Sniff 样本会把 URL 查询参数里的个人信息原样存下来；来源列表为空的 Sniff 项目对所有网站开放。

## 解决方案

页面桥只在本标签页正在执行 agent 任务或 TipScript 时可用，其余时候调用立即被拒绝。Hub 被 localhost 页面打开后不再自动连接，要我点「连接」才连。Sniff 对 URL 查询参数按请求体的同一套规则打码，只影响新录的样本。来源列表为空的项目不匹配任何网站，界面上提示我填写来源。

## 用户故事

- **US-1** 作为用户，我想要普通网页无法调用 `window.__pagenter` 的任何能力，以便我的模型额度、会话数据和登录态不被陌生网页利用。
- **US-2** 作为用户，我想要 agent 任务和 TipScript 运行期间，页面里的脚本仍能正常使用 `llm`、`kv`、`callApi`、`mcp`，以便现有功能不受影响。
- **US-3** 作为用户，我想要本地 MCP 启动页打开 Hub 后，由我点「连接」才去连它给的端口，以便本机任意网页不能替我决定 Hub 连哪里。
- **US-4** 作为用户，我想要 Sniff 新录的样本里，URL 查询参数中的敏感值被打码，以便样本和 Schema 示例里不出现个人信息。
- **US-5** 作为用户，我想要来源列表为空的 Sniff 项目不匹配任何网站，并在界面上看到提示，以便不会无意中把接口暴露给所有网站。
- **US-6** 作为维护者，我想要除这几处修复外，构建产物与原产物仍逐函数一致，以便确认没有顺手改动别的行为。

## 验收标准

### 页面桥

- **AC-1** 本标签页没有正在执行的 agent 任务或 TipScript 时，`__pagenter.llm`、`kv.*`、`callApi`、`listApis`、`mcp` 调用立即被拒绝，错误信息说明原因，不再等待 15 秒超时。〔覆盖 US-1〕
  - **怎么验**：后台测试检查授权判断函数在无活动会话、其他标签页有会话、本标签页有会话三种情况下的结果；真实页面 BOT-1 在普通网页上调用一遍。
- **AC-2** 本标签页正在执行 agent 任务或 TipScript 时，上述调用照常工作；任务结束后立即恢复为拒绝。〔覆盖 US-2〕
  - **怎么验**：后台测试检查会话开始、进行中、结束时的授权状态切换；真实页面 BOT-2 用 Script 模式和自动执行的 TipScript 各调用一次 `kv`。
- **AC-3** KV 按发起调用的标签页所属会话隔离，其他标签页的调用读不到、写不进。〔覆盖 US-1〕
  - **怎么验**：后台测试检查两个标签页、一个有会话一个没有时的读写结果。

### Hub

- **AC-4** 本地页面发 `OPEN_HUB` 后，Hub 打开并显示要连接的端口和「连接」按钮，不自动建立 WebSocket 连接；点「连接」后才连接。〔覆盖 US-3〕
  - **怎么验**：组件测试检查 Hub 带 `ws` 参数打开时显示待确认状态且未发起连接；真实页面 BOT-3 从 localhost 页面触发一次。
- **AC-5** `externally_connectable` 仍为 `http://localhost/*`，`OPEN_HUB` 的端口必须是 1 到 65535 的整数，否则忽略。〔覆盖 US-3〕
  - **怎么验**：纯函数测试检查端口校验；manifest 测试检查该字段未变。

### Sniff

- **AC-6** 新录样本的 URL 查询参数值按请求体的打码规则处理，样本 URL、`__query` 输入和 Schema 示例中都不出现原值；已存的旧样本不变。〔覆盖 US-4〕
  - **怎么验**：纯函数测试用带手机号、邮箱、token 的查询串检查打码结果；真实页面 BOT-4 录一个带查询参数的请求。
- **AC-7** 来源列表为空的项目不匹配任何网站；项目详情页对这类项目显示提示，引导填写来源。〔覆盖 US-5〕
  - **怎么验**：纯函数测试检查空列表不匹配；组件测试检查提示出现；真实页面 BOT-4 顺带检查。

### 范围控制

- **AC-8** 对比脚本里「不同」「仅一方有」只出现在本次修复涉及的函数上，并在开发完成报告里逐条列出、说明原因。〔覆盖 US-6〕
  - **怎么验**：运行对比脚本，人工走查差异清单与本 spec 一一对应。

### 主流程回归

会影响 agent 任务执行和 TipScript 自动执行两条主流程（页面桥授权）。还原工程没有 `pnpm e2e:regression`，用 BOT-2 加上还原 spec 的 BOT-2、BOT-5 手动回归一遍。

## 实现决策

- **页面桥授权在 background 判断**：用发起调用的标签页 id 查是否有正在执行的 agent 任务或 TipScript，不能只靠内容脚本或页面传来的参数。授权判断与 KV 的会话归属都以 `sender.tab.id` 为准。
- **TipScript 执行期间**登记为该标签页的活动会话，执行结束（成功、失败、超时）都要撤销。
- **Hub**：`OPEN_HUB` 只负责打开 Hub 并带上端口参数，连接改成由用户点击触发；端口不合法时忽略这次请求。
- **查询参数打码**复用请求体的打码规则，在样本入库前处理 URL 和 `__query`；不迁移旧数据。
- **空来源列表**：来源匹配函数对空列表返回不匹配，去掉原来的「放行所有来源」分支。
- 修复会让若干函数与原产物不再一致，这是预期；对比报告用来确认没有别的改动。

## 涉及层与路径

- **路径**：B 的简化版。改动的是已有页面（Hub、Sniff 项目详情），只新增一个待确认状态和一条提示，都能用现有组件拼出来，没有新组件，按路径 C 的条件判断成立，跳过线框图，不动 `DESIGN.md`（本工程没有）。
- **涉及层**：background（授权、KV、Sniff 打码、来源匹配）、content 与页面桥（错误回传）、界面（Hub、Sniff 项目详情）。
- **设计产物**：无。

## 不在范围内

- 迁移已存样本中的查询参数。
- 给 `window.__pagenter` 加网站白名单或逐站确认。
- 去掉 localhost 放行或改动 MCP 启动页本身。
- 其他未列出的行为改动。

## 补充说明

四项修复方向由用户在 2026-11-17 确认：页面桥只在活动任务期间可用；Hub 保留 localhost 放行但需用户点击连接；查询参数打码只影响新样本；空来源列表视为不匹配。
